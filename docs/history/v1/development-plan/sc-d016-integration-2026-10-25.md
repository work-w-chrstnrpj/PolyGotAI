## Confirmed defects repaired

1. Discovery accepted response bytes through a separate validator without SC-D015’s pinned policy/source/epoch/request lifecycle. A successful callback never settled the awaiting request. Responses now pass through `GeneratedPracticeSession.receive` exactly once; only its read-only validated result supplies the preview. Full policy/source checks apply. A malformed response settles failure, late/duplicate callbacks cannot overwrite drafts, and another explicit request may follow success/failure.
2. Topic/path/level/count/purpose could change while waiting and receive an old response under the new choices. Discovery pins the complete choices at request start, rejects changed choices or a different callback source, cancels local consumption, and clears the previous preview when a new request actually starts. View edits cancel an incompatible preview/request. No automatic retry.
3. Learner reset retained private topic/purpose choices and an old anchor/token. Binding another epoch now resets the entire discovery session, including drafts/request/source. Restart creates an empty memory-only session bound to the same epoch. Editing a hidden card-backed preview is ignored until explicit reveal. Leaving/backgrounding cancels preview consumption.
4. `WordOfDaySession.pin` accepted a missing epoch and overwrote an existing pinned sense, including within the same day. It now requires an epoch and refuses replacement. The exact qualified-review record must still match the available sense before display; changed wording retains its stored identity and is labelled. Epoch replacement drops the pin and committed snapshot. No automatic next-day selection is introduced.
5. The learner screen asked for internal objective/template/content/rubric IDs and enabled a Preview action without an available production policy. Those internal fields are removed from the product form; approved activity metadata must eventually come from the trusted contract. Generation stays disabled and its unavailability is explicit. A menu replaces the long segmented path labels for native layout flexibility. Preview/card containers preserve child accessibility identifiers. The daily-word screen no longer incorrectly claims a sense is absent from the learner’s collection.
6. Daily restart support was only an in-memory simulation. Optional `LearnerDocument.wordOfDay` now stores the pinned snapshot through current-epoch and exact-prior-record checks. Existing pins cannot be rewritten/rotated via storage; failed commits preserve the old document, reopen recovers the exact pin, and Delete all clears it and rejects stale saves. The host reads this record; production still supplies no selection/pin action or reviewed pool.
7. Returned files were absent from real targets/navigation. Three production files and the actual hosted tests are now registered (driver excluded). Vocabulary opens Topic word suggestions; Today opens Word of the Day. Both use the selected background and bind the current learner epoch. The daily screen refreshes local day on appearance, foreground, calendar-day, significant-time and timezone notifications.

## Delivery and missing implementation

Discovery’s topic/path/level/count/purpose draft is memory-only, not a saved generated topic. Production supplies no generation policy or transport; there is no provider request, request fan-out, enrollment, reward/assessment credit or automatic selection. The one-activity schema is a structural capability, not an adopted learner count default.

The provisional generation envelope does **not** carry topic/subtopic/purpose. A real topic-aware request contract, reviewed objective/template mapping, selected provider/adapter/model and semantic validation remain missing SC-T161/162 implementation. Do not claim that a synthetic vocabulary candidate is useful topic generation. Generated collection/review writes are deliberately blocked pending that contract and enrollment policy; manual save/review remains available.

Word-of-Day selection/repetition/reset defaults remain unadopted under SC-T161/055. No reviewed pool is supplied in production. `WordOfDayRecord` stores the shown snapshot and learner epoch as an optional Codable field in the existing protected learner document. `persist(expectedEpoch:using:)` prepares the exact record before writing; `recover` rejects a different epoch. Legacy documents decode without the new field. Tests use explicitly pinned synthetic reviewed fixtures and a real isolated repository reopen; production never seeds one. The app shows an honest empty/unavailable state until a reviewed pool and selection rules are delivered. Selected daily policy/pool and optional collection/review integration remain unfinished original SC-T167 requirements. No SwiftData migration or new learner store.

SC-T038/166/167 are `in_progress` because code/decisions/content remain missing. SC-T165 stays `awaiting_testing`; this pass does not reopen its manual feature or close original prerequisites. Scoped tests are not physical, provider, qualified content or learning acceptance.
